# 逆向方法论与踩坑记录

> 按时间顺序记录完整思路，重点是**每一步为什么这么走、哪里走通了、哪里走错了**。

---

## 阶段 0：抓包失败 → 转向静态分析

**原计划：** 抓官方 App 的蓝牙 HCI 日志，直接看它发了什么。

**两条路都断了：**

| 方法 | 失败原因 |
|---|---|
| Android 开发者选项「启用蓝牙 HCI 信息中心」 | 需要系统级权限，普通用户点不动 |
| `adb shell` 读 btsnoop | 手机未 root，`su` 不可用 |

**转向点：** 拿不到运行时流量，就从 APK 静态分析入手。协议构造逻辑一定在客户端代码里——这是离线逆源的常规路径，但一开始总想走"抓包最快"的捷径。

> **教训：先确认权限条件，再选技术路线。** 如果一开始就知道没 root，能省下两轮尝试。

---

## 阶段 1：解包 APK，定位协议代码

App 是 **uni-app** 打包，资源在：

```
assets/apps/__UNI__E392D13/www/
  app-service.js        4.1MB   ← 核心逻辑
  app-renderjs.js       8.7MB   ← 渲染层（无协议代码）
  app-config-service.js 289KB
```

**第一个弯路：** 直接搜 `"aa"` 只找到 4 个硬编码帧，看起来协议很简单。

**突破：** 顺着 `writeSpecialMode` 摸到了完整指令表——大部分帧是**运行时拼接**的（`"aa0a010" + i`），静态搜不到。

```js
writeSpecialMode(t){
  const o=["aa0A0101b6","aa0A0102b7",...,"aa0A010abf"][t];
  return this.writeData(o)
}
```

同时定位到三个核心函数：`Ce`（帧构造）、`nt`（马达数组）、`Oe`（强度映射）。

> **教训：搜常量搜不全，要顺着调用链走。** 运行时拼接的字符串必须找到构造函数。

## 阶段 2：把官方函数抠出来在 Node 里跑

**这是整个项目最关键的一步。**

静态读混淆代码容易看错。最可靠的办法是**把官方函数原样抽出来执行**，拿它的真实输出当基准。

`src/proto_extract.js` 的做法：

1. 用**括号深度匹配**从 `app-service.js` 切出目标函数（注意：要先跳过参数列表，否则默认参数 `n=[]` 里的花括号会导致截断）
2. 配上桩函数（`h` 日志、`nr` store、`te` state）
3. 在 Node 里执行并打印结果

```js
// 桩：让函数以为自己在正常运行环境里
var h = () => {};
var nr = () => ({
  deviceInfo: { motorNum: 1, prefix: "08", isXht: false },
  deviceArray: [], allFeatList: [],
});
```

**实测输出：**

```
Ce("08", [50])              = aa080132e5
Ce("06", [4,6,5])           = aa0603040605c2
nt([4,6,5], [], 1, false)   = [4]
Oe(50, [1], 1, false)       = [50]
```

**价值：** 我们的实现与官方逐字节一致。此后所有"某功能没反应"的排查都可以**直接排除帧格式问题**，把精力集中在设备行为上。

> **教训：能跑起来验证的，不要用眼睛看。** 混淆代码里一个符号看错，后面全盘皆输。

## 阶段 3：BLE 实测，逐个命令验证

有了正确的帧，开始实测。第一轮结果就推翻了 APK 的假设：

| 官方帧 | 实测 |
|---|---|
| `AA 08 01 <level>` | ✅ 立即生效 |
| `AA 04 01 <0/1>` | ✅ 加热正常 |
| `AA 06 05 <5字节>` | ⚠️ 有 ACK，无动作 |
| `AA 0A 01 <n>` | ❌ 完全无应答 |

**核心判断：这台机器的固件和 APK 指令表不是一套。** APK 要兼容多个机型，`writeSpecialMode` 服务的是老机型。

---

## 阶段 4：256 个命令字节全扫描

为了确认"只有 3 个命令"不是漏测，做了全扫描：每个命令字节发 2 种长度，用「有没有 ACK」做客观判据。

```
cmd 0x04  → aa 05 01 ...
cmd 0x06  → aa 07 05 ...
cmd 0x08  → aa 09 06 ...
其余 253 个 → 静默
```

**中途的假信号：** `0x3D`/`0xEF` 出现过"命中"。用单帧触发实验证伪——静默 12 秒后只发一帧，无应答。那只是周期状态帧碰巧赶到。

> **教训：客观判据也会被巧合污染。** 任何"命中"都要能复现，复现不了的就是噪声。

---

## 阶段 5：解析 ACK 与状态帧，寻找模式状态位

没有机载模式，那 `0x06` 到底做了什么？思路是找**客观反馈通道**。

**两次误判：**

| 误判对象 | 观察到的现象 | 证伪实验 |
|---|---|---|
| ACK 尾部字节 `<X>` | 有 `0xB0` / `0x30` 两种值，疑似状态位 | 强度 0 和强度 90 给出**完全相同**的值 → 滚动计数 |
| 状态帧第 5 字节 | 01→02→03→04→05 单调递增，疑似模式位 | 跨会话持续递增 → 命令计数器 |

**两次都靠"换条件看是否相关"证伪。** 状态位必须与输入相关，不相关的都是计数/校验。

---

## 阶段 6：量程标定——最大的实际收获

前面一直在找"更多功能"，但最有价值的发现来自一个简单问题：**强度到底能发到多大？**

```
发送   0 → ACK 回显 [0]
发送 100 → ACK 回显 [100]
发送 200 → ACK 回显 [200]
发送 254 → ACK 回显 [254]
发送 255 → 无应答        ← 被拒收
```

**真实量程 0–254。** 原版 App 滑杆只到 100，等于放弃 61% 量程——这很可能是大量用户觉得"不够猛"的根本原因。

**实现方式：** 逻辑强度(0-100) → 物理输出(0-254) 映射层。波形曲线内部仍按 0-100 设计（节奏形状不变），只在最终输出时缩放。一处改动，全链路生效。

> **教训：别只盯着"加功能"，基础参数的量程也可能一开始就是错的。**

## 阶段 7：帧率保护

多字节测试时连续发了 66 帧，`0x06` 的 ACK **完全消失**——设备在丢帧。

这正好对上最早期的用户反馈：「如果按的过快 飞机杯会没反应 切换不了」。根因是固件处理能力有限，不是软件逻辑错。

修法：协议层强制 **180ms 最小发送间隔**。

> **教训：用户描述的"灵异现象"往往是硬件限制。** 早期把它当 bug 查了太久。

## 阶段 8：服务端接口探测与登录墙

机型配置在服务端：

```
https://akn.ankeni.net/zqf/api/device/info/getDeviceLastStatus
```

服务端有**免 token 白名单**（仅 `player/*` 登录类）。带假 token 同样 401。

由于阶段 2 已证明 `prefix=08`、`motorNum=1` 与实际行为一致，这个缺口不影响结论。

## 通用踩坑清单

### 工程层面

1. **`str.replace` 不匹配时静默失败** —— 打补丁必须 `assert old in s`。本项目曾有两处替换静默丢失，导致"改了却没生效"，排查半天。
2. **QLabel 字面量初始化 + `setValue` 在 `connect` 之前** → 标签不更新。应在 connect 后显式同步一次。
3. **`QTimer.singleShot` 做启动页签切换不可靠** —— 改为 `show()` 后直接调用。
4. **父控件 stylesheet 设 `background: transparent` 会覆盖子控件的 objectName 样式** —— 滚动区内的按钮背景全丢，改成给滚动区设实色背景。
5. **`QVideoWidget.setFullScreen(True)` 后键盘事件不再冒泡到主窗口** —— 必须子类化重写 `keyPressEvent`，ESC 才收得到。
6. **PyInstaller `--windowed` 单文件首次启动要解包 25–35 秒** —— 自动化测试等待时间要够，否则误判"没起来"。
7. **Bash 后台启动的进程会在命令结束时被杀** —— "启动+等待+截图"必须写在同一条命令里。

### 逆向层面

1. **搜常量搜不全运行时拼接的字符串** —— 顺调用链找构造函数。
2. **抽函数要先跳过参数列表** —— 默认参数 `n=[]` 里的花括号会破坏括号深度匹配。
3. **ACK 存在 ≠ 功能存在** —— `0x06` 全程有 ACK，但什么都没做。
4. **周期上报会污染"命中"判断** —— 任何命中都要能复现。
5. **状态位必须与输入相关** —— 不相关的都是计数/校验。
6. **先确认权限条件再选路线** —— 没 root 就别规划抓包路径。
